# Implementation Plan: React Native Mobile App

**Branch**: `004-react-native-app` | **Date**: 2026-08-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/004-react-native-app/spec.md`

## Summary

Create a new React Native mobile app using Expo to allow users to authenticate, navigate, and view data on iOS and Android. The app will communicate with the existing `api-rust` production backend and adhere to the Wise-inspired design tokens.

## Technical Context

**Language/Version**: TypeScript, React Native

**Primary Dependencies**: Expo, Expo Router, `@tanstack/react-query`, `nativewind` (or custom StyleSheet theme)

**Storage**: `expo-secure-store` for session tokens

**Testing**: `jest`, `@testing-library/react-native`

**Target Platform**: iOS and Android (via Expo Go / simulators)

**Project Type**: Mobile Application

**Performance Goals**: Data fetch < 2s on stable connection, 60fps animations

**Constraints**: Must run against the live `api-rust` endpoints, maintain offline/error states

**Scale/Scope**: Adding a new client application to the monorepo alongside the web client

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **I. Nest–Rust parity**: The mobile app acts solely as a client and will connect directly to `api-rust/`.
- [x] **II. Tenancy**: The mobile app will transmit the required auth tokens to ensure the backend enforces RBAC and workspace isolation.
- [x] **III. Secrets**: No secrets are stored in this spec/plan.
- [x] **IV. Contracts**: We rely on the existing smoke tests in `api-rust/` for the endpoints we consume.
- [x] **V. Background work**: No new background jobs created.
- [x] **Stack**: Adds a new `mobile/` directory to the Yarn workspace (justified in Complexity Tracking).

### Source Code (repository root)

```text

client/              # React + Vite SPA
mobile/              # [NEW] React Native Expo Application
docker-compose.yml
```

**Structure Decision**: A new `mobile/` directory will be added to the Yarn workspace. While the constitution specifies `client/` for UI, `client/` is a React DOM web application. A mobile application requires a fundamentally different bundler (Metro/Expo) and native dependencies, warranting a separate workspace package.
